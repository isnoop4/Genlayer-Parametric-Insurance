How a policy settles

The same three steps every time — no manual review, no waiting on an insurer.

01

Buy a policy

Name a flight and a date, set a premium and a payout amount, and choose the delay threshold that counts as "late." The premium tops up the shared payout pool.

02

Validators check the flight

Calling check_and_settle sends five independent AI models to read the flight's actual status. GenLayer's consensus mechanism resolves their answers into one agreed delay figure.

03

Settlement is automatic

Delay at or above the threshold releases the payout immediately. Below it, the policy simply closes — no payout, no dispute.

Verify it yourself

Reproduce the two outcomes above directly in GenLayer Studio — no wallet needed beyond what Studio already provides.

01

Open the contract in GenLayer Studio

Go to studio-next.genlayer.com and load the deployed contract at 0x20Ab40D75D14C5BA33aFE14D4Ec6C3Dd9869E59f.

02

Fund the pool (once)

Under Write Methods → fund_pool, send a small amount so the pool can cover a payout (e.g. amount: 2).

03

Buy a policy

Under buy_policy, use the on-time example: flight_number: GIA406, flight_date: 2026-09-24, premium: 1, payout_amount: 1, delay_threshold_minutes: 60 — or the delayed example: flight_number: MXD388, flight_date: 2026-09-24, same other values. Note the returned policy_id.

04

Settle it

Under check_and_settle, pass that policy_id. GIA406 should return NO_PAYOUT; MXD388 should return PAID_OUT — matching the Equivalence Principle output shown in the transaction detail (status and delay_minutes read live from FlightAware).
